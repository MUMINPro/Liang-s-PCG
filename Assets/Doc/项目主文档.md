## 一、项目目标

做一套类似 PEAK 的攀爬地图生成系统（Unity 2022.3, URP）。
用户角色：**地图设计师 + 建模**（不负责攀爬手感/角色控制，那是别的岗）。
最终产物：一座可攀爬的立体山脉 —— 山脉/巨石/悬崖/藤蔓/洞穴，多条路线登顶。

核心理念：**分层程序化生成**。每层只管一件事，在上一层结果上叠加，层层让地图丰富。

## 四、已锁定的设计决策

1. **山体尺寸**：600m 画布、180m 峰高、240m 半径（可调）
2. **山形控制**：第1层 Falloff 曲线 = 山的剪影，拖曲线捏山形
3. **十种地貌**：石峰/岩脊/台地/峡谷/崖壁/悬垂/阶梯/巨石/洞口/缓坡
   —— 第2层只管几何形状；材质/水/植被归后续层
4. **地貌权重**：按海拔分层（山脚缓→峰顶险），每层带一张权重表，自然形成难度曲线
5. **多路登顶**：3 条主路从不同方位上山 + 横向连接段（藤蔓/岩架/洞穴/桥）互通
6. **第2层深层修法**（本次新决定）：
   - 地貌**真正修改山体网格**（石峰凸起、崖壁竖起、台地削平）
   - 第3层贴在这个真实地貌山面上，路线自然贴合地貌
   - **不再保留占位块实体**，只保留 **名称标签**（Scene 飘字）+ 底层数据
   - 真实精细模型由用户后续手工/商城资源摆放（基于标签和数据）
7. **环境标记接口**：第2层生成时打标记（峡谷→可蓄水、崖壁→可挂瀑布），供后续水体/材质层用

## 六、协作备忘（踩过的坑）

- **"生成了看不见"先查两件事**：① Scene 的 Gizmos 开关是否打开（Handles绘制靠它）
  ② Console 是否有红色编译错误（有错则新代码全部不生效）
- **Handles 标签/路网只在选中对应组件物体时显示**（OnSceneGUI 机制）
- **改 .cs 默认值不影响已存在的组件/资产**，需手动在 Inspector 改或重建
- **URP 材质**：用 `Universal Render Pipeline/Lit`，主色属性是 `_BaseColor`（不是 Standard 的 _Color）
- **删脚本成对删**（.cs + 它的 Editor），否则编译失败
- 所有生成器都**确定性**：同种子同配置 = 同结果

## 七、地形分块（Phase 1 + LOD 脚手架）

第1、2层地形已从单巨网格改为**分块网格**（`TerrainChunkBuilder.cs`）：
- 一张 res×res 高度场切成 MxM 块，每块 = MeshFilter/Renderer/MeshCollider + LODGroup
- **分块只是切网格**，山形/高度函数/地貌数据(heightDelta)不受影响，单一事实来源
- **法线解析计算**（对高度函数有限差分），跨块一致 → 零光照接缝
- 块边对齐全局网格索引、同分辨率 → 零裂缝零 popping
- 碰撞体每块全分辨率，与视觉 LOD 解耦
- 收益：视锥剔除（看不见的山背面不画）+ SRP Batcher 自动批 + 局部碰撞分摊
- 参数：第1层 Inspector 的 `resolution`(默认512) + `chunkVerts`(默认64顶点边)

**LOD 现状**：每块 LODGroup 只挂 LOD0（全模）。结构就位，以后加减面网格只是往
`lods[]` 里塞档位，不用重构。**何时加 LOD**：profiling 证明"整山全景视角 GPU 扛不住"时，
配裙边挡缝 + 碰撞固定分辨率 + cross-fade。600m 单山通常 Phase 1 已够。

## 八、第3层 v0.2：地形驱动寻路（路线服务于攀登）

v0.1 螺旋版的问题：路线是凭空数学螺旋、不认地形；连接按"距离近"乱撒、还穿山。
v0.2 改为**在攀爬代价场上寻路**：

- `ClimbCostField.cs`（新）：导航网格(默认96)，每格按**坡度+地貌**分三档：
  可走(缓坡/台地) / 攀爬(陡坡,高代价) / 屏障(崖壁/峡谷壁,徒手过不去)。
  预计算**辅助边**跨越屏障带，标记 Cliff(藤蔓/岩架) 或 Canyon(桥)。
  Dijkstra 在"普通格边+辅助边"上找最省力路径。
- `ClimbRouteGenerator.cs` v0.2：N个方位登山口逐条寻路到峰顶，
  **路线分离惩罚**逼各路分散；**营火按累积体力**放(不再按点数)；
  路径过屏障处自动标 `EdgeRole.Aid` + `BarrierKind`。
- **连接语义**（RouteEdge 新增 role/barrier 字段）：
  - `Aid` 必经辅助：路径被崖/谷挡住、唯一翻越手段 → 连接天生有目的、出现在真过不去处
  - `CrossLink` 可选捆绑：峰间藤蔓(PeakGap) + 相邻路线互通，都过**净空检查**不穿山
- 第4层 `ConnectionEntityGenerator`：藤蔓下垂点逐点抬到地表之上，悬链不再扎进山。

**关键参数**（第3层 Inspector）：navResolution(寻路精度)、nodeSpacing(点密)、
separationPenalty(路线分散度)、campfireEffortInterval(营火密度)、
generatePeakVines/maxPeakVineDistance(峰间藤蔓)、clearanceMargin(净空余量)。
